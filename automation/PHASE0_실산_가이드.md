# Phase 0 실측 가이드 — 사용자님이 직접 하실 작업 (30~50분)

> `automation/FLOW_UI_FACTS.md` 는 **빈 템플릿 상태**입니다. Antigravity가 만들어만 두고 채우지 못했습니다.
> 브라우저 로그인이 필요한 작업이라 AI가 대신할 수 없습니다. **F2·F3·F6 세 개만 채워도** 막힌 곳(R1~R3)이 풀립니다.
> 답은 `FLOW_UI_FACTS.md` 에 직접 적으시거나, 그냥 저에게 대화로 알려주셔도 됩니다.

## 준비 (5분)

전용 크롬을 원격 디버깅 모드로 띄웁니다. **평소 쓰는 크롬과 분리된 프로필**입니다.

```bat
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 ^
  --user-data-dir="C:\kd\chrome-profile"
```

그 창에서 → Google 로그인 → `labs.google/flow` 접속 → **프로젝트 하나를 "K-Destiny 자동화"로 새로 만들기**

> 처음 뜨는 프로필이므로 로그인을 새로 해야 합니다. 이 프로필의 로그인 세션이 앞으로 자동화의 인증 수단입니다.

## ★ F2. 모델 목록 (10분) — 가장 중요

모델 선택 드롭다운을 엽니다. **보이는 항목을 글자 하나 안 바꾸고 그대로** 적어주세요. 옆의 크레딧 숫자도 같이요.

```
예시 형식 (실제로 보이는 대로 채워주세요)

Veo 3.1 Quality              100 credits
Veo 3.1 Fast                  10 credits
Veo 3.1 Fast - Lower Priority  ? credits    ← 지금 쓰려는 것
Veo 3.1 Lite - Lower Priority  ? credits    ← 이게 더 싸면 이걸로 갈아탑니다
```

**함께 확인해주세요:**

- 드롭다운을 **여는 버튼**에 무슨 글자가 쓰여 있나요? (예: 현재 모델명이 그대로 표시 / "Model" / 톱니바퀴 아이콘만)
- 드롭다운을 닫은 뒤, **현재 선택된 모델이 화면에 어떻게 표시**되나요? (버튼 안에 모델명? 체크 표시만?)

> **왜 중요한가:** 코드가 `"veo3-fast"` 라는 문자열로 모델을 확인하는데, 실제 표기가 `Veo 3.1 Fast` 라면
> 문자열이 안 맞아서 검증이 항상 실패하거나 항상 통과합니다. 잘못 통과하면 **100크레딧 모델로 밤새 생성**될 수 있습니다.

## ★ F3. 출력 개수 (5분) — 크레딧 2배 여부가 갈립니다

Flow 설정에서 **"Outputs per prompt"**(프롬프트당 결과물 개수) 항목을 찾아주세요.

- 어디에 있나요? (오른쪽 사이드바 / 프롬프트창 옆 톱니바퀴 / 별도 설정 패널)
- **현재 값이 몇인가요?** ← 이게 핵심
- 선택 가능한 값은? (1 / 2 / 4 …)
- 1로 바꿔놓으세요.

> **왜 중요한가:** 이 값이 2면 **생성 1회당 크레딧이 정확히 2배** 나갑니다.
> 월 예산 계산(2,400크레딧)이 4,800이 되어 상한을 넘습니다. 지금 코드는 이걸 강제하지 못하고 조용히 넘어갑니다.

## ★ F6 + F5. 결과 타일과 Extend (15분) — 두 개를 한 번에

**아무 프롬프트로 8초 클립 1개를 생성**하세요. (예: `a single candle flame in darkness, cinematic, 9:16`)

### F6 — 결과가 쌓이는 위치

생성이 끝난 뒤:

- 결과가 화면 **어디에** 나타나나요? (하단 타임라인 / 오른쪽 갤러리 / 프롬프트 아래 목록)
- **한 번 더 생성해서 2개가 되면, 새 결과가 위에 쌓이나요 아래에 쌓이나요?** ← 이게 제일 중요합니다
- 다운로드 버튼이 **각 결과 안에** 있나요, 화면 상단 툴바에 하나만 있나요?

> **왜 중요한가:** 현재 코드는 "새로 만든 결과 = 화면 첫 번째 것"이라고 **추측**하고 있습니다.
> 만약 새 결과가 아래에 쌓인다면, 코드는 **매번 맨 처음 클립을 다시 다운로드**합니다.
> 그러면 완성본이 같은 8초 장면의 반복이 되는데, 로그에는 "성공"만 찍힙니다. 지금 가장 위험한 지점입니다.

### F5 — Extend가 누적본인지 새 구간만인지

방금 만든 8초 클립을 **Extend 1회** 하고, 결과를 다운로드하세요. 그리고:

```bat
ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 다운로드한파일.mp4
```

- 초기 클립 길이: ______초
- **Extend 후 다운로드한 영상 길이: ______초** ← 이 숫자 하나면 판정됩니다
  - **약 7초** → `delta` (새 구간만)
  - **약 15초** → `cumulative` (누적본)

> 현재 코드는 `cumulative` 로 **가정**해두었습니다. 틀렸으면 영상이 잘못 조립됩니다.
> ffprobe가 없으면 그냥 다운로드한 파일을 윈도 미디어 플레이어로 열어 총 길이를 보셔도 됩니다.

## F4. 크레딧 실단가 (5분) — 위 작업 중에 같이

F6/F5 생성을 하기 **직전과 직후**의 화면 크레딧 잔액을 적어주세요.

- 잔액이 화면 어디에 어떤 형식으로 뜨나요? (예: 우상단 `9,840 credits`)
- 생성 전: ______  → 생성 후: ______  → **차이: ______**
- Extend 1회의 차이: ______

> 코드는 10크레딧으로 설정돼 있습니다. 실측이 다르면 예산 계산 전체가 어긋납니다.
