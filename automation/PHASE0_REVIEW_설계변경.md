## 2. 【치명】 `Veo 3.1 - Fast [Lower Priority]` 는 **존재하지 않습니다**

실측된 모델 목록:

```
Omni Flash
Veo 3.1 - Lite
Veo 3.1 - Fast
Veo 3.1 - Quality
Veo 3.1 - Lite [Lower Priority]     ← Lower Priority는 Lite에만 있음
```

**우리가 쓰려던 조합이 목록에 없습니다.** 코드는 이렇게 되어 있습니다:

```python
MODEL_LABEL = "veo3-fast"
MODEL_PRIORITY_HINT = "Lower Priority"
```

`Fast` 이면서 동시에 `Lower Priority` 인 항목은 **하나도 없으므로**, 이 조건은 영원히 만족되지 않습니다.

### 이건 예상된 일이었습니다

제가 앞서 조사할 때 확인한 [Flow 공식 체인지로그](https://labs.google/fx/tools/flow/changelogs)와 정확히 맞습니다:

- **2025-11-25** — Ultra 구독자에게 Veo 3.1 Fast 무료(0크레딧) 생성 제공
- **2026-04-10** — **`Veo 3.1 Lite - Lower Priority`** 를 Ultra 대상 실험 옵션으로 도입

즉 Google이 **Fast의 Lower Priority를 없애고 Lite로 옮겼습니다.** 사용자님이 실제 화면에서 본 것이 그 결과입니다. 이제 이건 추측이 아니라 **직접 관측으로 확정된 사실**입니다.

### 결정이 필요합니다

| 선택지 | 크레딧 | 품질 | 큐 대기 | 판단 |
|---|---|---|---|---|
| **`Veo 3.1 - Lite [Lower Priority]`** | **0일 가능성 높음** | 낮음 (Lite) | 매우 길 수 있음 | **먼저 테스트할 것** |
| `Veo 3.1 - Fast` | 10~20 | 중간 | 짧음 | 안전한 기본값 |
| `Veo 3.1 - Quality` | 100 | 높음 | 짧음 | **절대 금지** (예산 즉사) |

**권고: Lite [Lower Priority]로 1편 만들어보고 품질을 눈으로 판단하세요.**
0크레딧이면 크레딧 문제 자체가 사라집니다. 우리 영상은 **마스터가 말하지 않고 존재하는** 정적인 연출이라(§보이스 설계 참조) Lite로도 충분할 가능성이 있습니다. 안 되면 Fast로 갑니다.

## 3. 【중대】 UI가 한국어라 영어 셀렉터 대부분이 무효입니다

URL에 `/ko/` 가 박혀 있습니다 → 버튼 텍스트가 전부 한국어입니다.

현재 코드의 셀렉터:

```python
'button:has-text("Download")'     # 화면에는 "다운로드"
'button:has-text("Generate")'     # 화면에는 "만들기" 또는 "생성"
'button:has-text("Extend")'       # 화면에는 (없음)
```

**해결책은 한국어 셀렉터를 추가하는 게 아니라, 로케일을 고정하는 것입니다.**

```python
# FLOW_PROJECT_URL 을 /en/ 으로 지정
https://labs.google/fx/en/tools/flow/project/<uuid>
```

이유: **셀렉터는 한 언어만 지원하면 됩니다.** 한/영 후보를 둘 다 넣으면 유지보수가 2배가 되고, Google이 한국어 번역을 바꿀 때마다 깨집니다. 영어 UI가 변경 빈도도 낮고, 문서·커뮤니티 정보도 영어 기준입니다.

→ `/en/` URL로 접속했을 때 UI가 영어로 바뀌는지 확인하고, 안 바뀌면 Google 계정 언어 설정을 영어로 바꾸세요.

## 4. 【중대】 크레딧 실측이 무효입니다 — 재측정 필요

기록된 내용:

> 생성 전 `25050` → 생성 후 `25010` (두 번 생성 + 1번 큐 대기 상태 기준), 총 40 차감

**이 숫자로는 단가를 알 수 없습니다:**

- "두 번 생성 + 1번 큐 대기"가 **2회 과금인지 3회 과금인지** 불명확
- 40 ÷ 2 = 20, 40 ÷ 3 = 13.3 — 어느 쪽인지 판정 불가
- 무엇보다 **측정 당시 출력 개수가 `1x`가 아니었을 가능성**이 큽니다 (F3에서 그때 1x로 설정했다고 기록됨). 2개 출력이었다면 실제 단가는 10일 수도 있습니다
- 어떤 모델로 생성했는지도 기록되지 않았습니다

**깨끗한 재측정이 필요합니다** — §7의 Phase 0.5에 절차를 넣었습니다.

### 부수적으로 확인된 것: 실제 한도는 25,000입니다

잔액 `25,050` 은 **Google AI Ultra 20x 등급(월 25,000 크레딧)** 입니다.

우리가 정한 **월 4,000 상한은 실제 한도의 16%** 에 불과합니다. 하루 2편을 안정적으로 돌리는 데 전혀 부족하지 않고, 오히려 나중에 테스트를 늘릴 여유가 큽니다. 지금은 4,000을 유지하되(안전장치로서 의미 있음), 나중에 필요하면 올리시면 됩니다.

## 5. ★★ Extend 부재 — 진단과 결론

### 5.1 "Extend가 없다"는 결론은 **측정이 불완전합니다**

사용자님이 확인한 건 **갤러리 타일의 '점 3개' 메뉴**입니다. 거기 없는 건 사실입니다. 하지만 [Google Flow 공식 문서](https://support.google.com/flow/answer/16935718)는 Extend를 이렇게 설명합니다:

> "장면을 더 길게 만들어야 한다면, 추가 footage를 만들어 원본 클립 **끝에 붙일 수 있습니다**"
> Scene Builder(씬 빌더)에서 클립에 마우스를 올리고 **"Add to Scene"** 을 선택한 뒤 편집합니다.

즉 **Extend는 갤러리가 아니라 Scene Builder 안에 있을 가능성이 높습니다.** Antigravity가 "기능이 없음"으로 단정한 건 성급했습니다.

### 5.2 그런데 — **우리는 이제 Extend가 필요 없습니다**

이게 진짜 결론입니다.

Extend는 **"마스터 한 명이 22초 동안 계속 이야기한다"** 는 옛 기획을 위한 장치였습니다. 그런데 시장조사 결과 포맷이 이미 바뀌었습니다:

```
[0-2s]  나레이터 후크 — "태어난 달, 지금 고르세요"
[2-10s] 1갈래 — 카르마
[10-18s] 2갈래 — 유라
[18-24s] 3갈래 — 류 + CTA
```

**이건 독립적인 장면 3개입니다.** Veo 3.1은 한 번 생성에 8초를 만듭니다. **8초 × 3 = 24초** — 정확히 우리가 필요한 길이입니다. **Extend가 개입할 자리가 없습니다.**

### 5.3 Extend를 버리면 얻는 것

| 항목 | 효과 |
|---|---|
| **미지원 리스크 소멸** | Flow가 Extend를 없애든 옮기든 우리와 무관 |
| **코드 대폭 단순화** | `EXTEND_DOWNLOAD_MODE`, cumulative/delta 분기, R5·R6 관련 로직 **전부 삭제** |
| **체크포인트가 깔끔** | 씬 1개 = 파일 1개. 재개 판정이 자명해짐 |
| **컷 전환 발생** | 22초 내내 같은 화면 대신 8초마다 장면 전환 → **시청 유지율 유리** |
| **자막 전환 자연스러움** | 씬 경계 = 자막 경계. Phase 4가 훨씬 쉬워짐 |
| **부분 재생성 가능** | 3번 씬만 마음에 안 들면 그것만 다시 생성 (크레딧 절약) |

**한 마디로: 결함이 아니라 기회였습니다.** 시장조사가 우리를 이미 옳은 방향으로 밀었고, Extend 부재가 그걸 확정해줬습니다.

### 5.4 새 아키텍처

```
변경 전:  영상 = 씬 1~3개, 각 씬 = 초기생성 + Extend N회 (연속 누적)
변경 후:  영상 = 독립 8초 씬 3개, Extend 없음
          scene_01.mp4 (8s) + scene_02.mp4 (8s) + scene_03.mp4 (8s) = 24s
```

**크레딧 계산 (편당 3생성):**

| 모델 | 편당 | 하루 2편 | 월(30일) | 4,000 상한 대비 |
|---|---|---|---|---|
| Lite [Lower Priority] (0이면) | 0 | 0 | **0** | 제약 없음 |
| Fast @ 10 | 30 | 60 | 1,800 | 45% |
| Fast @ 20 | 60 | 120 | 3,600 | 90% ⚠️ |

→ 단가가 20이면 빠듯하므로, **Lite [Lower Priority] 우선 테스트**가 더 중요해집니다.

### ① 로케일 영어로 고정 (2분)

주소창 URL의 `/ko/` 를 `/en/` 으로 바꿔 접속 → UI가 영어로 바뀌는지 확인.

안 바뀌면 Google 계정 언어를 영어로 변경.

### ② 모델을 `Veo 3.1 - Lite [Lower Priority]` 로 설정 + 출력 `1x` 확인 (2분)

### ③ 크레딧 깨끗하게 재측정 (5분) ★

```
1. 우상단 프로필 → 잔액 기록 ............... (   ) 크레딧
2. 프롬프트 1개로 생성 1회 (딱 한 번만)
3. 완성될 때까지 기다림

5. 차이 = Lite[Lower Priority] 실단가 ...... (   ) 크레딧
```

**0이 나오면 크레딧 걱정은 끝입니다.** 0이 아니면 같은 방법으로 `Veo 3.1 - Fast` 도 1회 측정해주세요.

### ④ 생성된 클립 길이 확인 (2분)

다운로드해서 파일 속성이나 재생기로 **총 길이 몇 초**인지 확인 → (   )초

### ⑤ ★ 다운로드 동작 관찰 (4분) — 가장 중요

타일의 **점 3개 → 다운로드** 를 클릭하면서 관찰:

- [ ] 크롬 하단/우상단에 **다운로드 진행 표시가 뜨는가?** (= 정상 다운로드 이벤트) → **예 / 아니오**
- [ ] 아니면 **새 탭이 열리는가?** → 예 / 아니오
- [ ] 화질(720p/1080p) **선택 팝업이 뜨는가?** → 예 / 아니오
- [ ] 저장된 **파일명 패턴**은? (예: `flow_20260726_xxx.mp4`) → (                    )
- [ ] 점 3개 메뉴에 **다운로드 말고 어떤 항목들**이 있는가? (전부 적어주세요)
      → (                                                          )

> 마지막 항목이 중요합니다. **"Add to Scene", "Scene Builder", "장면에 추가"** 같은 게 있으면 Extend 경로가 거기 있다는 뜻입니다. (지금은 안 써도, 나중에 더 긴 영상이 필요해지면 쓸 수 있습니다.)

### ⑥ (선택·10분) DOM 확인 — 하실 수 있으면
