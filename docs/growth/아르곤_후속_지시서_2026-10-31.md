## 16. 일주 페이지 → 궁합 바로 연결 — `argon/16-ilju-bridge`
**목적:** 일주 페이지로 검색해 들어온 사람이 궁합을 볼 때 자기 생년월일을 다시 넣지 않게 한다.

1. **`components/seo/IljuChecker.tsx` (일주 확인 칸)**
   - 기존 `CalendarTypeToggle`·`resolveRawDateToSolar`(`components/forms/BirthFields.tsx`)를 붙인다. 음력이면 양력으로 바꿔 `/api/ilju/check`에 보낸다.
   - 성별 선택 버튼 2개(여자/남자)를 추가한다. 선택은 필수이고 한 번 누르면 된다.
   - 확인에 성공하면 이동하기 직전에 `saveLastPerson({ name: "나", dob, time: null, gender })`(`lib/reportHandoff.ts`, sessionStorage·같은 탭에만)를 호출한다.
   - 안내 문구 "입력한 생년월일은 저장되지 않아요"는 이렇게 바꾼다: "입력한 생년월일은 서버에 저장하지 않고, 이 창을 닫으면 지워져요"
   - 생년월일은 URL·쿼리스트링·GA 이벤트 값에 절대 넣지 않는다.
2. **일주 상세 페이지(`app/[locale]/ilju/[slug]/page.tsx`)**
   - 본문 중간(속마음 섹션 뒤)과 맨 아래에 CTA 카드를 둔다.
     - 제목: "○○일주인 나 × 그 사람, 궁합은 몇 점일까?"
     - 버튼: "상대 생일만 넣고 무료로 보기" → `/ko/compat/new`
   - `CompatNewClient`는 lastCouple이 없으면 이미 `loadLastPerson()`으로 내 정보를 채운다. 이 동작이 실제로 되는지 확인만 하고, 안 되면 고친다.
   - 페이지는 서버 컴포넌트이므로 CTA는 작은 클라이언트 컴포넌트로 만든다.
3. **GA:** `ilju_check`에 `{ lunar: true|false }`를 추가하고, CTA 클릭에 `ilju_compat_cta_click { slug, position: "mid"|"bottom" }`을 단다.
4. **테스트**
   - 음력 입력이 양력으로 변환돼 API로 가는지
   - 성별을 안 고르면 제출이 막히는지
   - `saveLastPerson`이 호출되는지
   - CTA href에 생년월일이 없는지

## 17. 커플 상품 미리보기에도 스토리 카드 버튼 — `argon/17-teaser-story`
**목적:** 미리보기를 본 직후, 공유하고 싶을 때 바로 저장·공유할 수 있게 한다.

- `components/CompatNewClient.tsx`의 미리보기 화면에서 `SajuEightCharCard` 바로 아래에 기존 `components/share/StoryCardSaveButton.tsx`를 둔다.
  - 이미지 주소: `/api/og/story?compatId=<teaserResult.compatId>`
- 버튼 문구: "📸 우리 기운 카드 저장·공유"
- `source` 값은 `"compat_teaser"`로 한다. GA는 기존 `story_card_save`/`story_card_share`를 그대로 쓴다.
- 개인 상품 미리보기에는 달지 않는다. 그 이미지에는 상품 이름만 들어가서 의미가 적다.
- 미리보기 화면 버튼에서는 공유 보너스(+3)를 주지 않는다. 보너스는 한도 화면에서만 준다(기존 그대로).
- **테스트:** 미리보기 결과가 있을 때만 버튼이 렌더링되는지, 주소에 compatId만 들어가는지.
