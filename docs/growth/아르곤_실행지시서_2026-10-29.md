## 1. 작업 방식 (계속 이어서 일하기)

**작업 1개 = 브랜치 1개 = 커밋 1개.** 클로드가 앞 작업을 검토·배포하는 동안에도 다음 작업을 계속 진행한다.

1. 시작:
   ```
   git fetch origin
   git checkout -b argon/NN-이름 origin/main
   ```
   - 앞 작업에 기대는 작업(아래 "기반" 표시)은 그 브랜치에서 시작하고, REVIEW_HANDOFF.md에 기반 브랜치를 적는다.
2. 구현 → 검사(모두 통과해야 다음 단계):
   ```
   npx tsc --noEmit
   npx eslint <바뀐 파일>
   npx vitest run
   npm run build
   ```
3. 커밋 메시지: `feat(영역): 한국어 한 줄`. 끝에 `Co-Authored-By: Gemini Argon` 한 줄.
4. `git push -u origin argon/NN-이름` → REVIEW_HANDOFF.md 맨 위에 아래 5가지를 적는다(이 파일만 별도 커밋으로 main이 아닌 같은 브랜치에):
   - 바뀐 파일
   - 테스트 결과(통과 수)
   - 직접 화면에서 확인한 것
   - 스스로 의심하는 점
   - 클로드에게 필요한 것(법률 문구, 토큰, 광고 주소 등)
5. **main 푸시 금지, 배포 금지, `scripts/safe_deploy.py` 실행 금지.** 머지·배포는 클로드가 한다.
6. 같은 오류로 2번 이상 막히면 우회하지 말고 멈춘 뒤 상황을 적고 다음 작업으로 넘어간다.
7. 새 화면·버튼에는 GA4 이벤트(`trackEvent`)를 단다. 이름은 각 작업에 적힌 것을 쓴다.

## 3. 작업 명세 (이 순서대로)

### 01. 셀프 회원 탈퇴 — 브랜치 `argon/01-account-delete`
- **이유:** 카카오로 1초 만에 가입하는데 탈퇴는 이메일로만 된다. 가입보다 어려운 탈퇴는 위법 소지가 있다.
- **화면:** `/ko/me`(회원) 맨 아래 작은 "회원 탈퇴" 링크 → 확인 모달.
  - 문구: "열람 기간이 남은 리포트도 더 이상 볼 수 없어요"
  - 체크박스로 확인 → 탈퇴
- **API:** `DELETE /api/user/account`(세션 필수, 본인만). `app/api/admin/users/delete/route.ts`의 삭제 로직을 재사용한다.
  - 주문(Order)은 전자상거래법상 5년 보관이므로 삭제하지 않는다. 관계가 `onDelete: SetNull`인지 확인한다.
  - 끝나면 `signOut` 후 홈으로 보낸다.
- **GA:** `account_delete_open`, `account_delete_done`.
- **테스트:** 비로그인이면 401, 본인 계정만 삭제, 주문 행은 남는다.

### 02. 신년 시즌 전환 — `argon/02-season-2027` ⚠️ 11/1 0시 전에 끝낸다
- KST 2026-11-01 00:00부터 홈 히어로와 첫 추천을 `annual_2027` / `premium_2027_daeun` / `set_2027` 중심으로 바꾼다.
- 날짜 기준 자동 전환이고, 설정은 한 곳(예: `lib/season.ts`)에 둔다. 테스트는 시각을 주입해서 10/31 23:59과 11/1 00:00을 확인한다.
- 기존 기간 한정 가격 문구(12/31까지)는 카탈로그 값과 일치하게 유지한다. 새 "한정" 문구는 만들지 않는다.
- **GA:** `season_hero_view`(값: 2027).

### 03. 결제창 후기 보강 — `argon/03-checkout-review-fallback`
- **현재:** 그 상품 후기가 0개면 결제창 후기 영역이 숨는다(`components/product/ProductReviewsSection.tsx`, variant="checkout").
- **변경:** 같은 대상(커플 상품이면 커플 상품, 개인이면 개인)의 최근 실제 후기를 최대 2개 보여 준다.
  - 제목: "다른 리포트 구매자 후기"
  - 후기마다 그 후기의 상품명을 표시한다.
- `REVIEW_INCENTIVE_NOTE`(쿠폰 지급 표시)는 절대 지우지 않는다.
- **GA:** `checkout_reviews_fallback_view`.

### 04. 후기 요청 강화 — `argon/04-review-prompt`
- 리포트를 끝까지 읽은 사람(80% 스크롤 또는 마지막 섹션 노출)에게 기존 `components/report/ReviewCouponCard.tsx`를 화면 아래에서 한 번 띄운다. 닫으면 그 주문에서는 다시 띄우지 않는다(localStorage, try/catch).
- `/ko/me` 보관함에서 후기를 안 쓴 주문 행에 "후기 쓰고 1,000원 쿠폰" 작은 버튼을 단다.
- 쿠폰 금액은 1,000원 그대로다.
- **GA:** `review_prompt_view`, `review_prompt_click`.

### 05. 음력 생일 입력 — `argon/05-lunar-input`
- **대상 화면:** 궁합 입력(`/ko/compat/new`)과 개인 운세 입력 화면.
- **입력:** 생년월일 옆에 `[양력 | 음력]` 토글. 음력이면 `윤달` 체크박스를 보여 준다.
- **변환:** 제출 직전에 `lunar-javascript`로 양력으로 바꿔 기존 API에 그대로 보낸다.
  - 코드: `Lunar.fromYmd(y, 윤달 ? -m : m, d).getSolar()`
  - 없는 날짜·없는 윤달이면 "그해에는 윤○월이 없어요"라고 안내하고 제출을 막는다.
  - 변환은 별도 파일(`lib/lunarInput.ts`) + 단위 테스트로 만든다.
- **결과 화면:** "음력 ○월 ○일(양력 ○월 ○일)로 봤어요" 한 줄을 표시한다.
- **테스트:**
  - 음력 1990-01-01 → 양력 1990-01-27
  - 음력 2023 윤2월 1일 → 양력 2023-03-22
  - 없는 윤달은 거부
- **GA:** `lunar_toggle`(on/off).

### 06. 사주 여덟 글자 카드 + 매력 기운 배지 — `argon/06-saju-card`
- **목적:** "AI가 지어낸 글 아냐?"라는 의심을 첫 화면에서 없애고, 캡처해서 공유하고 싶게 만든다.
- **위치:** 무료 궁합 결과와 유료 상품 미리보기의 맨 위.
- **표시 내용 (한자 없이, 쉬운 말로):**
  - 두 사람 각각 8칸(연·월·일·시, 시간을 모르면 "모름"). 각 칸에는 "큰 나무", "촛불", "바다" 같은 쉬운 이름과 색을 넣는다.
  - 다섯 기운 막대: 나무·불·흙·쇠·물의 개수.
- **매력 기운 배지:** 엔진 계산으로 **있을 때만** 단다.
  - "도화(사람을 끄는 매력)", "홍염(한 번 빠지면 깊은 매력)", "역마(움직임이 많은)"
  - 퍼센트·순위·"상위 ○%"는 금지다.
- **계산은 결정론:** `lib/saju.ts` 결과를 읽기만 하는 새 파일 `lib/sajuDisplay.ts`에서 계산하고, 단위 테스트를 단다(같은 입력이면 같은 카드, 배지 판정 경계값).
- **GA:** `saju_card_view`, `charm_badge_view`(배지 이름).

### 07. 인스타 스토리용 결과 카드(9:16) — `argon/07-story-card` (기반: 06)
- **버튼:** 무료 궁합 결과와 무료 성격 결과에 "스토리용 카드 저장"을 단다.

  - 하단 워터마크: `kongdak.kr`
  - 생년월일·실명은 넣지 않는다(애칭만, 없으면 "나 × 그 사람").
- **공유:** 모바일에서 `navigator.share({ files })`가 되면 바로 공유하고, 안 되면 이미지를 다운로드한다.

### 08. 공유하면 오늘 3번 더 — `argon/08-share-bonus` (기반: 07)

### 09. 반쪽 초대장 완성 알림 — `argon/09-invite-push`
- 초대장이 완성되는 지점(`app/api/compat/invite` 완성 처리)에서, 만든 사람이 회원이고 푸시 구독(PushSubscription)이 있으면 웹 푸시를 보낸다.

  - "상대의 진짜 속마음이 열렸다" 같은 사실이 아닌 표현은 금지다.
- 받는 사람 결과 화면 하단에 "이 사람이 나를 어떻게 생각하는지 궁금하다면 → 그 사람 속마음 보기"를 넣는다(`inner_mind` 미리보기로 이동, 입력은 재사용).

### 10. 연말 시즌 기획전 — `argon/10-season-events`

- 종료되면 일반 상품 목록으로 바뀐다(자동).
- "○일 남음"은 실제 종료일로 계산한다. 종료일은 한 곳(설정 파일)에서 관리하고 테스트로 확인한다.
- 각 화면에 메타데이터를 넣는다. sitemap에는 넣지 않는다(기간 한정).
- **GA:** `season_view`(시즌 이름).
- 광고 주소(`/ko/go/tt-xmas*` 등)는 클로드가 만든다 → REVIEW_HANDOFF에 화면 경로만 적는다.

### 11. 일주 페이지 60장 — `argon/11-ilju-seo`
- **경로:** `/ko/ilju/[slug]` 60장(갑자일주 ~ 계해일주). 제목은 "갑자일주 연애 성향과 잘 맞는 사람"처럼 한글만 쓴다.
- **600장 대량 생성은 금지**(검색엔진 저품질 처리). 대신 한 장을 두껍게 만든다.
  - 섹션 4개: 연애 성향 / 속마음 표현 방식 / 이별·재회 패턴 / 잘 맞는 일주 3개(내부 링크)
  - 섹션마다 `id` 앵커를 달고, 소제목에 검색어를 넣는다(예: "갑자일주 여자 속마음").
- **본문:** 결정론 데이터(일주별 성향 키워드)를 바탕으로 한 번만 생성해서 `lib/seo/ilju.ts`에 정적 데이터로 저장한다. 요청 때마다 AI를 부르면 안 된다. 단정 예언 금지.
- **입력:** "내 일주 확인하기"에서 생년월일을 넣으면 `lib/saju.ts`(읽기 전용)로 일주를 계산해 해당 페이지로 이동한다. 생년월일은 URL에 넣지 않는다.
- **구조:** 기존 `/ko/zodiac/*`의 메타데이터·JSON-LD·sitemap 구조를 따른다. IndexNow 제출은 클로드가 한다.
- **GA:** `ilju_view`, `ilju_check`.

### 12. 차액만 내고 세트로 바꾸기 — `argon/12-set-upgrade` ⚠️ 결제 코드
- **가격 인하가 아니다.** 단품 결제 후 24시간 안에, 그 단품이 들어 있는 세트를 **세트 가격 − 이미 낸 금액**에 연다.
  - 예: 속마음 4,900원 결제 → 설렘 세트(7,900원)를 3,000원에.
- **위치:** 결제 완료 화면, 해당 리포트 하단.
  - 문구: "이미 낸 4,900원은 빼고 3,000원만 내면 세트로 바뀌어요"
- **서버:** `/api/payments/order`가 `upgradeFromOrderId`를 받는다.
  - 서버가 다음을 **모두** 검증한다:
    - 같은 소유자(회원 userId 또는 비회원 orderId 토큰)
    - PAID
    - 24시간 이내
    - 같은 compatId
    - 세트에 그 단품이 포함됨
    - 이미 업그레이드한 적 없음
  - 금액은 **서버가 계산**한다(최소 100원). 클라이언트 금액은 무시한다.
  - Order에 `upgradeFromOrderId String?`를 추가한다(additive). 웹훅 경로에서도 같은 금액 검증을 한다.
  - PAID가 되면 세트 Unlock을 같은 compatId로 준다. 기존 단품 Unlock은 그대로 둔다.
- **테스트:** 남의 주문 거부, 24시간 초과 거부, 서버 금액 계산, 이중 업그레이드 거부, 웹훅 금액 검증.
- **GA:** `upgrade_offer_view`, `upgrade_offer_click`, `purchase`에 `upgrade: true`.

### 13. 운세 선물하기 — `argon/13-gift` ⚠️ 결제 코드
- **보내는 쪽:** 상품 화면과 결제 완료 화면에 "선물하기" 버튼 → 받는 사람 애칭과 한 줄 메시지 → **정가 그대로** 결제 → 선물 링크(코드) 생성 → 카카오톡 공유.
- **받는 쪽:** 링크를 열면 "○○님이 2027 신년운세를 선물했어요" → **받는 사람이 자기 생년월일을 직접 입력** → 리포트 생성.
  - 보낸 사람은 받는 사람의 생년월일을 볼 수 없다.
  - 커플 상품을 선물받으면 받는 사람이 두 사람 정보를 입력한다.
- **규칙:**
  - 코드 1개 = 지정 상품 1건
  - 사용 기한은 결제일부터 90일
  - 쓰지 않은 선물은 환불 대상(관리자 화면에서 미사용 표시)
  - 금액 충전식·잔액 차감식은 금지
- **DB:** `GiftCode` 테이블 추가(additive).
  - 컬럼: 코드(추측 불가), 상품 id, 구매 Order, 메시지, 애칭, 사용 여부, 사용 Order·시각, 만료일
  - 사용 처리는 **트랜잭션 + `updateMany where used=false`**로 한 번만 되게 한다.
- **테스트:** 두 번 사용 거부, 만료 거부, 다른 상품으로 사용 거부, 결제 안 된 코드 거부.
- **GA:** `gift_click`, `gift_purchase`, `gift_open`, `gift_redeem`.
- 약관·방침의 선물 조항은 클로드가 쓴다 → REVIEW_HANDOFF에 "선물 조항 필요"라고 적는다.

### 14. 두근이에게 묻기 (질문 3개 답장 리포트) — `argon/14-ask-three` ⚠️ 결제·AI
- **상품:** `ask_three` "그 사람에 대해 묻고 싶은 3가지", **4,900원**. 한 번에 사는 콘텐츠 1개다(충전·차감 없음).
  - 질문 3개를 쓰고 결제하면 답장 3개가 리포트 1개로 나온다. 더 물으려면 다시 산다.
- **위치:** 커플 리포트(속마음·궁합·재회 등) 맨 아래에만 보인다.
- **답의 근거:** 같은 compatId의 결정론 결과와 기존 리포트 요약.
- **추천 질문 칩:**
  - "내가 먼저 연락하면 어떨까?"
  - "이번 달 안에 만나자고 해도 될까?"
  - "그 사람이 원하는 연락 속도는?"
- **안전장치(필수, 테스트 포함):**
  - 건강·법률·돈·임신·자해·폭력·제3자 실명·연락처 질문은 **결제 전에** 걸러서 정중히 안내한다.
  - 단정 금지. 오락 목적임을 고지한다.
  - 생성에 실패하면 재생성하고, 그래도 안 되면 자동 환불 경로를 탄다(기존 실패 처리 방식 확인).
  - 프롬프트는 `lib/prompts/`에 둔다(클라이언트 import 금지).
- **GA:** `ask_open`, `ask_question_chip`, 구매는 `purchase`.
- 약관 가격 목록은 클로드가 고친다 → REVIEW_HANDOFF에 적는다.

### 15. 서버에서 구매 신호 보내기 (메타 CAPI·틱톡 Events API) — `argon/15-capi`
- 결제가 PAID로 바뀌는 곳(`lib/payments/grant.ts`의 `applyPaidOrder`)에서 메타 Purchase, 틱톡 CompletePayment를 서버로 보낸다.
  - 값: `value`, `currency: KRW`, 상품 id
- **중복 제거:** 브라우저 `purchase`의 eventID 규칙을 찾아서 같은 event_id를 쓴다.
- **보낼 수 있는 값:** IP, User-Agent, `_fbp`/`_fbc`/`_ttp`/`ttclid` 쿠키값.
  - 주문 생성 시 서버에서 읽어 Order `adSignals Json?`에 저장한다(additive).
  - **이름·전화·이메일 해시는 보내지 않는다.**
- **토큰:** `.env`의 `META_CAPI_TOKEN`, `TIKTOK_EVENTS_TOKEN`. 없으면 조용히 건너뛴다. 토큰을 코드·로그·문서에 쓰지 않는다.
- 비동기로 보내고 try/catch와 3초 타임아웃을 건다. **실패해도 결제 처리는 절대 막지 않는다.**
- 개인정보처리방침 수정은 클로드가 한다.
