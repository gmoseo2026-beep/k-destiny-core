## 0. 반드시 지킬 것 (먼저 읽기)

1. **저장소 규칙:** `AGENTS.md`, `skill.md` §5(보안)를 먼저 읽고 따른다. 이 Next.js는 학습 데이터와 다르다 — `node_modules/next/dist/docs/` 확인.
2. **원문 리포트의 경로·API 이름을 믿지 말 것.** 실제와 다른 게 섞여 있다.
   - `/api/orders/claim`, `/api/payments/prepare`는 없다. 실제는 `/api/user/claim-unlock`, `/api/user/claim-device-orders`, `/api/payments/order`.
   - robots.txt는 AI 검색 봇(ChatGPT-User, OAI-SearchBot, PerplexityBot)을 이미 허용 중이다. 학습용 봇만 막혀 있다 → 손대지 않는다.
   - NHN KCP는 쓰지 않는다(이니시스만).
   - 모든 경로는 `grep`으로 직접 확인하고 쓴다.
3. **건드리지 말 것:** `lib/saju.ts`, `lib/trueSolarTime.ts`, `lib/compatibility.ts`의 계산 로직. 읽기(import)만 가능.
4. **DB:** 추가(additive) 마이그레이션만. 기존 컬럼·테이블 삭제·변경 금지.
5. **"use client" 파일**은 `lib/prompts/*`, `lib/destinyGen`, `lib/premium/generate*`, `lib/gen/*`를 타입으로만 import(`tests/clientPromptLeak.test.ts`).
6. **개인정보:** 생년월일·이름·전화·이메일을 로그·광고 픽셀·URL에 넣지 않는다.
7. **금지(법·정책):**
   - 가짜 후기·가짜 숫자·지어낸 퍼센트("상위 4%", "확률 89%" 등 엔진이 계산하지 않은 수치).
   - 다크패턴(전자상거래법 2025-02 시행): 비싼 옵션 **사전 선택**, 가짜 카운트다운, 실제로 끝나지 않는 "한정".
   - 연예인·실존 인물 이름을 쓴 궁합 페이지(퍼블리시티권).
   - 할인 쿠폰 신설·가격 인하(사장님 결정: 가격 인하 하지 않음). 기존 후기 쿠폰 1,000원만 유지.
   - 포인트 충전·묶음 이용권·구독(위험업종 회피).
8. **말투:** `lib/destinyGen.ts` STYLE_GUIDE — 한자 금지, 단정 예언 금지, 다정하고 쉬운 말. 사주 용어는 아래 일주 SEO 페이지의 "○○일주" 표기만 예외.
9. **작업 방식:**
   - 브랜치 `growth/argon-1029`에서 작업. **main 직접 푸시 금지, 배포 금지**(배포는 클로드가 검토 후 `scripts/safe_deploy.py`로).
   - 작업 1개 = 커밋 1개(`feat(...): ...` 한국어 한 줄).
   - 커밋마다 `npx tsc --noEmit` → `npx eslint <바뀐 파일>` → `npx vitest run` → `npm run build` 모두 통과.
   - 새 화면·버튼에는 GA4 이벤트(`trackEvent`)를 단다. 이벤트 이름은 각 작업에 적은 것을 쓴다.
   - 끝나면 `REVIEW_HANDOFF.md`에 작업별로 기록한다: 바뀐 파일, 테스트 결과, 스스로 의심하는 점.

## 1. 이번 주 (P1) — 순서대로

### T1. 셀프 회원 탈퇴 (법적 필수)
- **이유:** 카카오로 1초 만에 가입하는데 탈퇴는 이메일로만 된다. 가입보다 어려운 탈퇴는 위법 소지가 있다(정보통신망법·개인정보보호법).
- **화면:** `/ko/me`(회원) 맨 아래에 작은 "회원 탈퇴" 링크 → 확인 모달("열람 기간이 남은 리포트도 볼 수 없어요" + 체크박스 확인) → 탈퇴.
- **API:** `DELETE /api/user/account`(세션 필수). `app/api/admin/users/delete/route.ts`의 삭제 로직을 재사용하되 본인만.
  - 주문(Order)은 전자상거래법상 5년 보관이므로 삭제하지 말고 `userId`만 끊는다(스키마가 이미 `onDelete: SetNull`인지 확인).
  - 끝나면 `signOut` 후 홈으로.
- **GA:** `account_delete_open`, `account_delete_done`.
- **테스트:** 비로그인 401, 본인 계정만 삭제, 주문 행은 남는다.

### T2. 결제창 후기 보강 (가짜 없이)
- **현재:** 상품에 후기가 0개면 결제창 후기 영역이 숨는다(`ProductReviewsSection` variant="checkout").
- **변경:** 그 상품 후기가 0개면 **같은 대상(커플 상품이면 커플 상품, 개인이면 개인)의 최근 후기 최대 2개**를 보여 주고, 제목을 "다른 리포트 구매자 후기"로 바꾼다. 상품명도 함께 표시한다.
- 쿠폰 지급 표시 문구(`REVIEW_INCENTIVE_NOTE`)는 그대로 유지(이미 들어가 있음, 지우면 안 됨).
- **GA:** `checkout_reviews_fallback_view`.

### T3. 후기 요청 강화 (쿠폰 금액은 그대로 1,000원)
- 리포트를 끝까지 읽은 사람(리포트 화면 80% 스크롤 또는 마지막 섹션 노출)에게 기존 `components/report/ReviewCouponCard.tsx`가 화면 하단에 한 번 떠오르게 한다. 닫으면 그 주문에서는 다시 안 띄운다(localStorage).
- `/ko/me` 보관함의 각 리포트 행에 후기를 안 쓴 주문이면 "후기 쓰고 1,000원 쿠폰" 작은 버튼.
- **GA:** `review_prompt_view`, `review_prompt_click`.

### T4. 음력 생일 입력
- 궁합 입력(`/ko/compat/new`)과 개인 운세 입력 화면의 생년월일 옆에 `[양력 | 음력]` 토글, 음력이면 `윤달` 체크박스.
- 제출 직전에 `lunar-javascript`(이미 의존성에 있음)로 양력으로 바꿔서 기존 API에 그대로 보낸다: `Lunar.fromYmd(y, 윤달 ? -m : m, d).getSolar()`.
  - 없는 날짜(예: 그해 윤달이 없는데 윤달 체크)는 입력창 아래에 "그해에는 윤○월이 없어요"라고 안내하고 제출을 막는다.
- 결과·리포트 화면에는 "음력 ○월 ○일(양력 ○월 ○일)로 봤어요" 한 줄 표시.
- 계산 엔진은 건드리지 않는다(변환은 입력 단계에서만).
- **테스트:** 음력 1990-01-01 → 양력 1990-01-27, 음력 2023 윤2월 1일 → 양력 2023-03-22, 없는 윤달 거부.
- **GA:** `lunar_toggle`(값: on/off).

### T5. 인스타 스토리용 결과 카드(9:16) 저장·공유
- 무료 궁합 결과와 무료 성격(`free_personality`) 결과에 "스토리용 카드 저장" 버튼.
- `app/api/og/` 기존 OG 이미지 패턴을 따라 1080×1920 이미지를 만든다.
  - 내용: 두근이, 점수, 엔진이 낸 키워드 3개, 한 줄 요약.
  - 하단 워터마크: `kongdak.kr`
  - **엔진이 계산하지 않은 수치·퍼센트·"상위 ○%" 금지.** 생년월일·실명은 이미지에 넣지 않는다(애칭만, 없으면 "나 × 그 사람").
- 모바일: `navigator.share({ files })` 지원 시 바로 공유, 아니면 이미지 다운로드.
- **GA:** `story_card_save`, `story_card_share`.

### T6. 미리보기 한도에서 "공유하고 3번 더 보기"
- 하루 무료 미리보기 한도 모달(`PreviewLimitModal` 등, 실제 파일 확인)에 버튼을 추가한다: "결과 카드 공유하고 오늘 3번 더 보기".
- 공유(T5 카드 또는 링크 공유)가 끝나면 서버에서 **그 기기(kd_vid)의 오늘 한도를 +3** 해 준다. 하루 1회만.
  - 서버 한도 로직을 찾아서 같은 곳에서 처리한다. 클라이언트 숫자만 바꾸는 방식 금지.
- 공유했는지 확인할 수 없으므로 공유 시트를 연 것으로 인정한다(문구에 "공유하면"이라고만 쓰고 강요하지 않는다).
- **GA:** `preview_bonus_share`.

### T7. 반쪽 초대장 완성 알림 + 받는 사람 다음 행동
- 초대장이 완성되면(`app/api/compat/invite` 완성 처리 지점), 만든 사람이 회원이고 푸시 구독이 있으면 웹 푸시를 보낸다.
  - 문구: "○○님이 반쪽을 채워서 두 분의 궁합이 완성됐어요 💌" → 결과 링크.
  - **"상대의 진짜 속마음이 열렸다" 같은, 사실이 아닌 표현 금지.**
- 받는 사람(B)의 결과 화면 하단 문구: "이 사람이 나를 어떻게 생각하는지 궁금하다면 → 그 사람 속마음 보기"(기존 `inner_mind` 미리보기로 연결, 입력 재사용).
- **GA:** `invite_complete_push_sent`, `invite_receiver_cta_click`.

## 2. 다음 주 (P2) — P1을 클로드가 검토·배포한 뒤 시작

### T8. 결제 직후 "차액만 내고 세트로 바꾸기"
- **가격 인하가 아니다.** 단품 결제 후 24시간 안에, 그 단품이 들어 있는 세트를 **세트 가격 − 이미 낸 금액**에 열어 준다. 예: 속마음 4,900원 결제 → 설렘 세트 7,900원은 3,000원.
- 노출 위치:
  - 결제 완료 화면
  - 해당 리포트 화면 하단
- 표시 문구: "이미 낸 4,900원은 빼고 3,000원만 내면 세트로 바뀌어요".
- **서버(가장 중요):**
  - `/api/payments/order`에 `upgradeFromOrderId`를 받는다.
  - 서버가 다음 조건을 **모두** 확인한다:
    - 그 주문이 같은 소유자(회원 userId 또는 비회원 orderId 토큰)의 것
    - PAID
    - 24시간 이내
    - 같은 궁합(compatId)
    - 세트에 그 단품이 포함됨
    - 이미 업그레이드한 적 없음
  - 금액을 **서버가 계산**한다(최소 100원). 클라이언트 금액은 신뢰하지 않는다.
  - Order에 `upgradeFromOrderId String?` 컬럼 추가(additive).
  - 결제 완료 시 세트 Unlock을 같은 compatId로 부여한다. 기존 단품 Unlock은 그대로 둔다.
- **테스트:** 남의 주문 거부, 24시간 초과 거부, 금액 서버 계산, 이중 업그레이드 거부, 웹훅 경로에서도 동일 금액 검증.
- **GA:** `upgrade_offer_view`, `upgrade_offer_click`, 구매는 기존 `purchase`에 `upgrade: true`.
- ⚠️ 결제 코드라서 클로드가 한 줄씩 검토한 뒤 배포한다.

### T9. 11월 1일 신년 시즌 전환
- KST 2026-11-01 00:00부터 홈 히어로·첫 추천을 `annual_2027` / `premium_2027_daeun` / `set_2027` 중심으로 바꾼다(날짜 기준 자동 전환, 설정 한 곳에서).
- 기존 기간 한정 가격 문구(12/31까지)는 실제 카탈로그 값과 같게 유지. 새 "한정" 문구를 만들지 않는다.

### T10. 메타 전환 API(CAPI)·틱톡 Events API — 서버에서 구매 신호 보내기
- 결제가 PAID로 바뀌는 곳(`lib/payments/grant.ts`의 `applyPaidOrder`)에서 Purchase(틱톡은 CompletePayment)를 서버로 보낸다.
  - `value`, `currency: KRW`, 상품 id.
  - **브라우저 픽셀과 같은 event_id(주문 id 기반)로 중복 제거.** 현재 브라우저 `purchase`가 쓰는 eventID를 찾아 같은 규칙을 쓴다.
- 보낼 수 있는 것: IP, User-Agent, `_fbp`/`_fbc`/`_ttp`/`ttclid` 쿠키값.
  - 주문 생성 시 서버에서 읽어 Order에 `adSignals Json?`(additive)로 저장한다.
  - **이름·전화·이메일 해시는 보내지 않는다**(사장님이 고른 개인정보 원칙).
- 토큰은 `.env`의 `META_CAPI_TOKEN`, `TIKTOK_EVENTS_TOKEN`. **없으면 아무것도 안 하고 조용히 넘어간다.** 토큰을 코드·로그·문서에 쓰지 않는다.
- 실패해도 결제 처리는 절대 막지 않는다(비동기, try/catch, 짧은 타임아웃).
- 개인정보처리방침 문구 수정은 클로드가 한다(건드리지 말 것).

### T11. 60일주 연애 성향 SEO 페이지
- `/ko/ilju/[slug]` 60개(갑자일주 ~ 계해일주). 페이지 제목은 "갑자일주 연애 성향과 잘 맞는 사람"처럼 한글만, **한자 금지**.
- 본문은 결정론 데이터(일주별 성향 키워드)를 기반으로 쓴다. 문장은 한 번만 생성해서 `lib/seo/ilju.ts` 같은 정적 데이터로 저장하고, 사람이 읽고 다듬을 수 있게 한다(요청 때마다 AI 호출 금지).
- 각 페이지에 들어가는 것:
  - "내 일주 확인하기": 생년월일 입력 → `lib/saju.ts`를 읽기 전용으로 써서 일주 계산 → 해당 페이지로 이동
  - 궁합 보기 버튼(`/ko/compat/new`)
- 기존 `/ko/zodiac/*` SEO 페이지 구조(메타데이터·JSON-LD·sitemap)를 그대로 따른다. sitemap에 추가하고, 배포 후 IndexNow 대상에 넣는다(스크립트는 클로드가 돌림).
- 단정 예언 금지("반드시 ~한다" X → "~한 편이에요").

### T11 보강 (10-29 재검토) — 600장이 아니라 "60장을 두껍게"
- 같은 틀에 단어만 바꾼 페이지를 수백 장 찍으면 구글은 "대량 생성 저품질(scaled content abuse)", 네이버는 "유사 문서"로 보고 **사이트 전체 노출을 깎는다**. 그래서 600장은 만들지 않는다.
- 대신 일주 페이지 60장 각각에 섹션 4개를 둔다: **연애 성향 / 속마음 표현 방식 / 이별·재회 패턴 / 잘 맞는 일주 3개(링크)**. 섹션마다 `id`(앵커)와 소제목에 검색어를 넣는다(예: "갑자일주 여자 속마음").
- 일주끼리 서로 링크해서 60장이 하나의 백과사전처럼 묶이게 한다.
- 배포 4주 뒤 서치콘솔에서 노출이 큰 주제만 별도 페이지로 쪼갠다(클로드가 데이터로 판단).

### T12. 운세 선물하기 (선물 코드)
- **누가 사나:** 연말·설날에 부모님·친구·연인에게 "2027 신년운세", "우리 궁합"을 선물하는 사람. 받는 사람은 새 손님이 된다.
- **방식:** 상품 화면과 결제 완료 화면에 "선물하기" 버튼 → 받는 사람 애칭과 한 줄 메시지 입력 → **정가 그대로** 결제 → 선물 링크(코드) 생성 → 카카오톡 공유.
- **받는 쪽:** 링크를 열면 "○○님이 2027 신년운세를 선물했어요" → 받는 사람이 **자기 생년월일을 직접 입력** → 리포트 생성. 선물한 사람은 받는 사람의 생년월일을 알 수 없다.
- **규칙:**
  - 코드 1개 = 지정 상품 1건, 사용 기한은 결제일부터 90일.
  - 쓰지 않은 선물은 구매자가 환불 요청 가능.
  - 금액 충전식·잔액 차감식 금지(상품권·포인트가 되면 안 됨).
- **DB:** `GiftCode` 테이블 추가(additive) — 코드, 상품 id, 구매 주문, 사용 여부, 사용한 주문·시각, 만료일. 사용은 **트랜잭션 + 조건부 update**로 한 번만.
- **GA:** `gift_click`, `gift_purchase`, `gift_open`, `gift_redeem`.
- 약관·개인정보처리방침 문구(선물 조항)는 클로드가 쓴다.

### T13. 연말 시즌 기획전 (새 상품을 만들지 않는다)
- 기존 세트에 시즌 이름을 붙인 **기획전 화면**만 만든다(가격·구성은 기존 그대로, 새 할인 없음).
  - `/ko/season/christmas`: "크리스마스 전에, 그 사람 마음" → 속마음·설렘 세트·확신 패키지.
  - `/ko/season/before-new-year`: "올해 가기 전에 정리하고 싶은 사람" → 재회 세트·재회운·갈등과 해법.
  - 솔로용: "내년엔 연애할까" → 연애운·매력 세트(set_love)·2027 신년운.
- **마감은 진짜로:** `/ko/season/christmas`는 12/25 23:59, 나머지는 12/31 23:59에 자동 종료(기획전 화면이 일반 상품 목록으로 바뀜). 화면의 "○일 남음"은 실제 종료일로 계산한다.
- 광고 주소(`/ko/go/tt-xmas1` 등)는 클로드가 `lib/campaignLinks.ts`에 추가한다.
- **GA:** `season_view`(시즌 이름), 상품 클릭은 기존 이벤트.

### T14. 두근이에게 묻기 (질문 3개 답장 리포트) — 결제한 사람의 두 번째 결제
- **포인트·이용권이 아니라 "한 번에 사는 콘텐츠 1개"로 만든다:** 상품 `ask_three` "그 사람에 대해 묻고 싶은 3가지", **4,900원**(다른 단건과 같은 가격).
  - 손님이 질문 3개를 한 번에 쓰고 결제하면, 답장 3개가 한 리포트로 나온다.
  - 추가 질문은 다시 이 상품을 사는 방식이다(충전·차감 없음).
- **어디에 보이나:** 커플 리포트(속마음·궁합·재회 등) 맨 아래에만. 같은 궁합(compatId)의 결정론 결과와 기존 리포트 요약을 근거로 답한다.
- **추천 질문 칩:**
  - "내가 먼저 연락하면 어떨까?"
  - "이번 달 안에 만나자고 해도 될까?"
  - "그 사람이 원하는 연락 속도는?"
- **안전장치(필수):**
  - 건강·법률·돈·임신·자해·폭력 관련 질문은 답하지 않고 정중히 안내(결제 전에 거른다).
  - 제3자 실명·연락처 질문 거부.
  - 단정 금지("반드시 연락 온다" X).
  - 오락 목적 고지.
  - 생성 실패 시 자동 환불 또는 재생성.
- 카탈로그에 상품을 추가하면 약관 가격 목록은 클로드가 고친다.
- **GA:** `ask_open`, `ask_question_chip`, 구매는 `purchase`.

### T15. 사주 여덟 글자 카드 + 매력 기운 배지 (무료 미리보기 맨 위)
- **목적:** "AI가 지어낸 글 아냐?"라는 의심을 첫 화면에서 없애고, 공유하고 싶게 만든다.
- **한자 없이 쉬운 말로 보여 준다:**
  - 두 사람 각각 8칸 카드: 연·월·일·시(시간 모르면 "모름"). 각 칸은 "큰 나무", "촛불", "바다" 같은 쉬운 이름과 색.
  - 다섯 기운 막대: 나무·불·흙·쇠·물의 개수.
- **매력 기운 배지:** 엔진 계산 결과로 **있을 때만** 표시한다.
  - "도화(사람을 끄는 매력)", "홍염(한 번 빠지면 깊은 매력)", "역마(움직임이 많은)" 등.
  - 없는 걸 있다고 하거나 퍼센트·순위를 붙이지 않는다.
- **계산은 반드시 결정론:** `lib/saju.ts` 결과를 **읽기만** 해서 만든다(새 계산 함수는 `lib/sajuDisplay.ts` 같은 별도 파일 + 단위 테스트). 같은 입력은 항상 같은 카드.
- T5 스토리 카드에도 이 배지를 넣는다(사람들이 가장 많이 캡처해 올리는 요소).
- **GA:** `saju_card_view`, `charm_badge_view`(배지 이름).
